# Чат с героем истории: RAG и тестовый чат

Чат из `docs/brainstorm/2026-10-29-character-chat.md` и `docs/notes/chat-rework.md`: у каждой истории свой герой, читатель говорит от себя. Сейчас два чата: «Золотая клетка» (Сююмбике, 1533 год) и «По хребтам Сихотэ-Алиня» (Арсеньев, 1900 год).

## Запуск

```bash
cp chat/.env.example chat/.env   # вписать AI_API_KEY (OpenRouter)
task chat:ingest                 # нарезать корпус и посчитать эмбеддинги
task chat:serve                  # http://localhost:8765
```

Справа на странице открывается панель отладки. В ней можно:
- выставить выборы читателя из эпизода 1 (переменные ink) и сразу увидеть, что из них попадёт герою;
- посмотреть найденные сведения с весами, сам промпт, задержку, токены и цену;
- искать по корпусу вручную.

Другие команды:
- `task chat:search -- "вопрос"` — поиск, каким его видит герой (фильтр по году карточки; `--story` выбирает историю);
- `task chat:wiki` — перекачать статьи Википедии;
- `task chat:test` — тесты и линтер.

## Как устроено

| Где | Что |
|---|---|
| `content/chat/rules.md` | правила роли, общие для всех героев |
| `content/stories/<история>/chat/` | контент героя одной истории, его пишет сценарист: `card.yaml` (имя, год, место, голос, словарь, имена для поиска, кто есть кто), `epNN.lore.md` (общий для всех канон главы), `epNN.state.yaml` (переменные ink главы в слова). Все главы пока подмешиваются вместе, выбор прочитанных появится со второй главой |
| `chat/corpus/` | база знаний для RAG: Markdown с front matter (`source_id`, `title`, `layer`, `rights`, `cite`, `url`, `event_year`, `story`: только герой этой истории находит фрагмент, без поля его видят все) |
| `chat/rag/corpus.py` | нарезка по разделам и абзацам примерно по 900 знаков; год события на каждый фрагмент; разрез там, где текст переходит к более позднему году |
| `chat/rag/index.py` | гибридный поиск: косинус по эмбеддингам `baai/bge-m3` + BM25 по русским основам (Snowball), слияние RRF, не больше 3 фрагментов на источник; кэш эмбеддингов в SQLite |
| `chat/rag/hero.py` | герой одной истории и сборка промпта: постоянная часть (правила, карточка, время, канон) + состояние + найденные сведения; мягкие проверки ответа |
| `chat/rag/server.py` | FastAPI: `/api/chat` (SSE: `sources`, `delta`, `done`), `/api/summary`, `/api/stories`, `/api/search`, `/api/state`, `/api/report`; в каждом запросе поле `story`, роли реплик `hero` и `reader` |
| `chat/web/index.html` | тестовая страница чата |
| `chat/data/` | индекс, кэш, логи `chats.jsonl` и `reports.jsonl` (не в git) |

### Слои и год

У каждого фрагмента есть `layer` и `event_year`. Герой ищет только в `fact` и `setting`, и только среди фрагментов с годом не позже года из его карточки (`year`). Фрагменты без года проходят фильтр, поэтому разделы о будущем без явной даты нужно размечать вручную или обрезать (так сделано со статьями об Арсеньеве, Владивостоке и Сихотэ-Алине: они кончаются там, где кончается знание героя 1900 года). `task chat:wiki` качает статьи, `uv run python -m rag fetch-wiki --story sikhote-alin` только статьи одной истории; `future_pattern` в `card.yaml` задаёт слова, выдающие будущее героя. Пометка ставится строкой под заголовком:

```markdown
## Семья
<!-- meta: event_year=1549 -->
```

Слои: `canon`, `fact`, `setting`, `fiction`, `legend`, `interp`. Повторная загрузка Википедии не затирает файлы с такими пометками.

Проверить разметку: `uv run python -m rag chunks` (в `chat/`) печатает каждый фрагмент с его слоем и годом.

### Проверки ответа

Проверки ничего не блокируют, а только показывают флаги в отладке:
- `future` — годы позже 1533 или признаки будущего;
- `anachronism` — слова из `lexicon.never`;
- `out_of_role` — герой вышел из роли;
- `stage_direction` — ремарки в `*звёздочках*`;
- `too_long` — больше 60 слов;
- `crisis` — герой вышел из роли по правилу «Кризис».

## Дизайн

Страница нарисована дизайн-системой «Наследия» (это инструмент разработчика; в приложении чат оформлен нейтральным китом оболочки, см. `docs/notes/chat-rework.md`) (`docs/brainstorm/templates/DESIGN.md`) и её Blender-китом: `/kit/*.png` раздаётся из `heritage/png3d`. 1 CSS px равен 1 единице игрового канваса 360×780. Спрайты рисует маленький порт `KitImage.cs` на canvas: 9-slice по `slices.txt` и целые плитки по краям. Обычный CSS `border-image` оставляет на стыках срезов волосяные швы, поэтому от него отказались.

| Что | Спрайт |
|---|---|
| реплика героя | `plate` + бирка `label` слева (как `PlateSkin.Plain`) |
| реплика читателя | `chat-veil` (новый: газ дымчатой мяты, розовый пунктирный шов) + бирка `label-rose` справа |
| выход из роли, ошибка | `plate-rose` + `label-rose` |
| поле ввода, отправка | `chat-field`, `chat-send` (новые) |
| отладка | `page` |
| значки | `round` + маска `restart`, `gear`, маски `exit`, `flag` (новая) |

Новые спрайты описаны в `heritage/blender/chat3d.py`. Рендер: `blender -b --factory-startup --python-exit-code 1 -P blender/render.py -- chat-veil chat-chip chat-field chat-send chat-bead chat-bead-out flag` (из `heritage/`). Новый материал `gauze` добавлен в `studio.py`.

## Модель

`z-ai/glm-5.3-flash` через OpenRouter. Размышление у неё не отключается, поэтому идёт с `effort: low`, а его текст не возвращается. Замер 29.10.2026: около 3,8 тыс. токенов на входе, ответ около 5 с, примерно $0,0005 за реплику.
