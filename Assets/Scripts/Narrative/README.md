# Narrative — движок визуальной новеллы

Чистая логика: читает скомпилированные ink-истории (`.json` от inklecate) и превращает
их в последовательность «битов» для показа. Не знает ничего про Unity, рендер, звук и
время: сборка `LegacyThroughTime.Narrative` помечена `noEngineReferences` и собирается
под `netstandard2.1` отдельно от Unity (`task test`).

```
Json/      разбор и запись JSON без зависимостей
Ink/       рантайм ink: загрузчик JSON → граф, виртуальная машина, сейвы
Machine/   автомат визуальной новеллы поверх рантайма + «наш стиль»
```

Зависимости идут строго вниз: `Machine → Ink → Json`.

## Модель

### Верхний уровень: `StoryMachine`

Автомат Мили с расширенным состоянием

M = (Q, Σ, Λ, V, δ, λ, q₀, v₀)

| | |
|---|---|
| Q  | `StoryPhase`: Ready, Line, Directive, Choice, End, Fault |
| Σ  | { Advance, Choose(i) } — всё, что может сделать игрок |
| V  | состояние ink: глобальные переменные, счётчики посещений, стек вызовов… |
| Λ  | `Beat`: что показать + Δ переменных, которую вызвал переход |
| δ, λ | `Advance()` / `Choose(i)` |

Свойства (каждое проверяется тестами на всём корпусе историй):

- **Тотальность δ через охранные условия.** Вход, не разрешённый в текущем
  состоянии, отклоняется (`false`) и не меняет ни q, ни V.
- **End и Fault поглощающие.**
- **Инварианты выхода.** Choice ⇔ есть варианты; у Line всегда есть текст; у Directive —
  теги.
- **Детерминизм.** Одна история + один seed + одна последовательность входов = одна и та же
  последовательность битов. Сейв эквивалентен паре (seed, входы).
- **Load ∘ Save = id** с точностью до наблюдаемого поведения, а сам сейв — неподвижная
  точка: `Save(Load(Save(s))) = Save(s)`.
- **Композиция дельт.** vₙ = v₀ ⊕ Δ₁ ⊕ … ⊕ Δₙ: проиграв все `Beat.Changes`, получаем
  текущие значения переменных.

### Нижний уровень: `InkRunner`

Та же модель, только с магазинной памятью: управляющее состояние — счётчик команд
текущего фрейма, расширенное — (стек потоков/фреймов, стек вычислений, поток вывода,
глобальные переменные, счётчики, ход, seed). `Step()` — функция переходов δ, `Continue()`
итерирует её до границы строки.

Где кончается строка, нельзя решить без заглядывания вперёд: склейка `<>` в следующей
строке может отменить перевод строки. Поэтому на каждом `\n` снимается снапшот, и
заглядывание потом либо фиксируется, либо откатывается ровно:

- **управляющая часть** (стек, вывод, выборы) маленькая — копируется в заранее
  выделенный запасной курсор, в устойчивом режиме без аллокаций;
- **данные** (переменные, счётчики) переходят в режим журнала: каждая запись сохраняет
  (слот, старое значение), откат проигрывает журнал в обратном порядке, то есть
  применяет обратную дельту. Стоимость O(записей), а не O(размера состояния).

Решение «съела ли склейка перевод строки» принимается по дописанному хвосту вывода:
пока из вывода ничего не удалялось, очищенный текст — это префикс, заканчивающийся `\n`,
плюс хвост, а очистка пробелов такой префикс не меняет. Всё, что сложнее (теги, удаления),
идёт по эталонному определению.

Всё, что официальный рантайм разрешает на каждом шаге (пути диверсий, цели выборов,
контейнеры счётчиков, имена глобальных переменных), здесь разрешается один раз при
загрузке: переменные — это слоты массива, счётчики — массивы по плотному id контейнера.

## Совместимость с ink

Семантика совпадает с официальным рантаймом ink 1.2.1 (формат JSON v21, читаются v18–v21):
текст, склейка и пробелы, теги (в том числе динамические и на выборах), выборы всех видов,
fallback-выборы, туннели, функции (включая `ref`-параметры), потоки `<-`, чередования
и перемешивания, счётчики и `TURNS_SINCE`, `RANDOM`/`SEED_RANDOM` (генератор совпадает
бит-в-бит), списки `LIST`, `EXTERNAL` с запасными ink-функциями, вызов функций из кода,
`ChoosePathString`. Не реализованы параллельные «flows» (`SwitchFlow`) и `ContinueAsync`.

Это проверяется дифференциально: `Tests/Narrative` проигрывает корпус историй и все
эпизоды игры на нашем движке и на официальной `ink-engine-runtime.dll` с одинаковыми
seed и случайными выборами и сравнивает каждую строку, теги, варианты выбора и все
глобальные переменные после каждой строки (десятки тысяч строк за прогон), вставляя
по пути save/load.

Отличие от эталона, сделанное намеренно: деление на ноль — ошибка истории, а не падение
процесса; числа печатаются в инвариантной культуре (официальный рантайм под ru-RU
напечатал бы `1,5`).

## Наш стиль (`StoryStyle`)

- Реплика: `Имя: текст` → `Beat.Speaker` + `Beat.Text`. Поэтому двоеточие после первых
  слов строки без тега читается как реплика; для ремарок используйте `# narr`.
- Теги голоса: `# narr`, `# thought`, `# system`, `# flashback`, `# sfx` → `Beat.Voice`.
  Имя говорящего разбирается только в диалоге и во флешбэке.
- Прочие теги — `ключ: значение` (`# bg: steppe_dawn`) → `Beat.TagValue("bg")`.
  Тег на отдельной строке относится к следующей строке текста; если за тегами нет
  текста (дальше выбор или конец), получается бит Directive.
- Платный вариант: `💎 Взять нож (5 💎)` → `IsPremium`, `Cost = 5`, `Text = "Взять нож"`.

Всё это — данные в `StoryStyle`, их можно поменять, не трогая автомат.

## Использование

```csharp
var story = InkStory.FromJson(json);          // один раз, неизменяемая, можно шарить
var m = new StoryMachine(story);              // одно прохождение

m.BindExternal("play_sound", args => { /* … */ return null; });

m.Advance();
switch (m.Current.Phase)
{
    case StoryPhase.Line:   Show(m.Current.Speaker, m.Current.Text, m.Current.Voice); break;
    case StoryPhase.Choice: ShowOptions(m.Current.Options); break;   // затем m.Choose(i)
    case StoryPhase.End:    Finish(); break;
}
foreach (var d in m.Current.Changes) Toast($"{d.Name}: {d.Before} → {d.After}");

var save = m.Save();   // строка JSON
m.Load(save);
```
